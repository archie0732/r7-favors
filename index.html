MAKE IT YOURS

三步建立自己的工具庫。

公開網站放程式與公開收藏，私人資料放在另一個 Private Repository。兩者由最小權限 Token 安全連接。

01

複製並設定 Repository

Fork 這個專案後，編輯 config.js 的 publicSource，換成自己的 owner、Repository 名稱、branch 與資料路徑。私人庫不必寫進設定檔。

Fork 這個工具庫 ↗
02

建立最小權限 Token

Settings → Developer Settings → Fine-grained tokens → Generate new token。Repository access 選 Only select repositories，Permissions 只加 Contents，依用途設 Read-only 或 Read and write，產生後立刻複製。

建立 Fine-grained token ↗
03

從頁面新增連結

公開頁按「管理」；私人頁在解鎖表單直接貼上私人 Repository 連結與 Token。驗證後按「新增項目」，填入標題、網址、類型、標籤與縮圖，再儲存。

REPOSITORY ACCESS

Token 權限怎麼選？

Metadata 的 Read 權限由 GitHub 自動提供。這個網站只需要 Contents，不需要 Actions、Administration 或帳號密碼。

公開瀏覽不需要 Token
私人瀏覽Contents · Read-only
新增／修改／縮圖Contents · Read and write
第一次設定的完整檢查清單
  1. 建立公開 Fork，並在 config.js 設定 publicSource。
  2. 另外建立 Private Repository。在私人頁的解鎖表單貼上它的連結（owner/repo 或 GitHub 網址）即可連接；config.js 的 privateSource 只是預設值，可留空。
  3. 建立 Fine-grained token：填 Token name、設定 Expiration（選 No expiration 會被 GitHub 警告）。
  4. Repository access 選 Only select repositories，只勾要用的庫；確認顯示 Selected 1 repository。
  5. Permissions → Add permissions → 搜尋 conte → 勾 Contents，需要編輯時把 Access 改成 Read and write（Metadata 由 GitHub 自動加入）。
  6. 按 Generate token 後立刻複製 github_pat_…；它只顯示一次，忘了複製就 Delete 重做。
  7. 開啟私人頁，貼上 Repository 與 Token；資料檔不存在時，按「建立預設 JSON」。頁面內的「第一次連接私人 Repository？」有完整步驟。
  8. 到 Settings → Actions → General 允許 Actions，再到 Settings → Pages 選擇 main 與 /(root)。

不要：把 Token 放進 config.js、網址、README 或任何 commit，也不要把私人 JSON 放進公開 Fork。
